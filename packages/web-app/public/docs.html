poptart, from scratch

A livecoding instrument that plays real plugins from terse patterns.

Thirteen short studies, each building on the last. Read them in order once and you'll be able to play; after that, dip in for whatever you need. Keep the editor open in the other tab and try each idea as you meet it — everything here is plain text you can paste and bend.

The one-sentence version: you write little patterns, poptart turns them into notes and knob-turns, and sends those to actual VST/VST3 instruments and effects running inside a SuperCollider audio engine. The real thing, modulated continuously while it plays.

Study 0

The editor & the loop

The whole workflow is one gesture: type, then evaluate. Cmd/Ctrl + Enter plays what's in the editor; Cmd/Ctrl + . stops. Re-evaluating swaps the running sound out from under itself without a gap — that's the livecoding part. (update re-evaluates without touching play/stop.)

A buffer is split into blocks. A block that starts with a label — a name and a colon at the start of a line — is a track: 

bass: note("c2 c2 g1 a1").synth("Serum 2")
drums: s("bd*4, ~ hh ~ hh")

Two labels, two tracks, playing together. Call them whatever you like. Lines that continue an expression (a .param(…) chain) stay attached to the block above, so one track can span many lines.

  • _bass: (or bass_:) mutes a track without deleting it.
  • Sdrums: solos it — if anything is soloed, only soloed tracks play. Mute still wins.

Anything that isn't a labelled track — a bare line, or a $: block — runs as setup: shared consts, language extensions, one-off calls like setbpm(128). A named block must evaluate to a pattern.

panels The sidebar has four tabs. session: the live tracks and macro knobs. sounds: your plugins, their parameters, your samples. files: save and load buffers. settings: audio device, sample folder, editor options, the startup prebake.
nothing gets lost Whatever is in the editor is autosaved as a work in progress under the month you played it (bottom of the files tab; ⤓ keeps one under a real name). Give a pattern a title in a comment and it names itself everywhere — // @title kick drift, // @by aria @tags techno — and the search box finds it by name, tag or code (tag:techno, by:aria). Every evaluation is also a browser-history entry, so Back walks you through what you played.
help as you type Autocomplete (it opens by itself, or Ctrl + Space) shows each name with its signature and a one-line description. Hold Ctrl and hover over anything already written to see the same thing. That reference is the short form of this guide.

Study 1

Everything is a signal

Here's the one idea that makes the rest click. A signal is a value that changes over time. A melody is a signal. An LFO is a signal. A single number is a (boring) signal. They're all the same kind of thing, so they all compose the same way.

Some signals have edges — a note pattern "c e g" has three steps per cycle, so poptart knows exactly when each note starts and stops. Others are smooth — an LFO has no steps, it's just read wherever a value is needed. The same machinery handles both.

The unit of time is the cycle (a bar). setbpm(120) sets the tempo — 4 beats per cycle, so 120 bpm is two cycles a second. Whatever you write in a pattern string fills exactly one cycle, then repeats.

Because signals compose, the interesting verbs are the ones that combine and reshape them — .add(), .range(), .when() — and they don't care whether they're holding a melody, an LFO or a knob. Keep "a value that changes over time" in mind and the API stops being a list to memorise.

Study 2

Mini-notation: the string language

The strings inside note("…"), s("…"), .param("…", "…") and friends are a tiny rhythm language borrowed from Tidal and Strudel. Space-separated items divide the cycle evenly; ~ is a rest: 

"0 1 2 3"        // four equal steps
"0 ~ 2 ~"        // two notes, two gaps
SyntaxMeans
[a b]Sub-group: the pair shares one step's worth of time.
a b, c dStack: comma layers voices that play at once.
<a b c>Alternation: one per cycle, round and round.
a*4Fast: four as in its slot. The rate can be a pattern — a*<2 3>.
a/2Slow: stretch a across two cycles.
a!3Replicate: three separate a steps.
a@3 bWeight: a takes 3× the room of b.
a _ _Tie: _ extends the previous note.
bd.e(3,8)Euclidean: 3 hits over 8 steps, held until the next hit. Every argument takes a pattern — 1.e(<3 5>,8).
a? / a?0.3Degrade: randomly drop the step (30% here).
a|b|cRandom choice, one per cycle.
r · i(a,b) · pRandom float 0..1 · random integer · slow perlin drift.
(c2 + 12)Expression: mini-notation with + - * /. Note names are their MIDI number.

These nest freely — "<[0 2] [3 5]>*2" does what it looks like. Inside (...), * glued to a value is still fast (2*4) but spaced out it's multiply (2 * 4); put a space before a -. Polymeter {a b, c d} isn't in yet.

tip The randomness in ?, |, r, i and p is deterministic per cycle: a given bar plays the same each time it comes round, and the editor's playback highlight always agrees with what you hear.

Study 3

Notes, degrees, and scales

note(…) is absolute pitch: note names or MIDI numbers, note("c4 e4 g4"), note("60 64 67"). c5 = 60, as in Strudel; sharps and flats are c#4 / db4.

n(…) is scale degrees: 0 is the root, 1 the next note up, 7 the octave — and they mean nothing until you name the scale: 

n("0 2 4 6").scale("F minor")   // degrees → the notes of F minor

A scale is "<root> <mode>" — "F minor", "c dorian", "Bb mixolydian". The usual modes, pentatonics, blues, harmonic/melodic minor and chromatic are all there, with the common aliases.

snap to key .scale() on a note(…) pattern does the other sensible thing: it snaps each note to the nearest pitch in the scale. note("c4 e4 f#4 g4").scale("C major") bends the f# into an f. The same snap applies to notes played live from a MIDI keyboard, so played and written lines land on the same pitches.
one key, one edit A patch is nearly always in one key, so the key can live in the document: setscale("F minor") sets it and .sc() reads it. 
setscale("C minor")

bass: n("0 3 5").sc(3).synth("Serum 2")    // root in octave 3
lead: n("0 2 4 7").sc(5).synth("Diva")
setscale is hoisted: the last one in the buffer is the key the whole buffer plays in, including the patterns above it. Re-keying a set is one edit, wherever it's convenient to make it. The piano roll follows along.

Notes work on either side of the instrument, and the pitch kind survives arithmetic — note("c4 f#4").add(12).scale("C major") still knows it's holding notes. A bare synth("…") with no notes plays a C2 every cycle, so a fresh instrument makes sound while you decide what it should play.

Study 4

The piano roll

pianoroll() is a note pattern you draw instead of type: 

lead: pianoroll().synth("Serum 2")   // double-click the word pianoroll

Double-click the name and a grid opens over the editor — a piano keyboard down the side, a loop bar along the top, a playhead sweeping as it plays. Draw; every stroke is written back into the code and re-evaluated, so what you hear is always what's on screen. Rolls are named (a bare pianoroll() names itself after its track), their notes are filed in a folded pianorolls block at the foot of the buffer, and the names pattern like anything else: pianoroll("<verse chorus>"). The panel's ▾ finds or creates rolls, ⧉ copies one.

The options are { grid, len, start }: grid cells per cycle, len cells in the loop, start the cell the loop window opens on. So { grid: 16, len: 24 } is a bar and a half of sixteenths. Drag the loop bar's ends (or its middle) rather than typing them. Notes outside the window stay drawn, dimmed, and silent.

At the grid

move / resize / copydrag · drag the right edge · option-drag
nudgearrow keys; shift+↑↓ an octave, shift+←→ lengthens/shortens

The value lane

Along the bottom, one marker per note. Click its label to flip it between vel, prob (a per-note ?) and nudge (a per-note timing offset). With the arrow tool, dragging moves the whole selection together; with the pencil, you paint — sweep across and every note snaps to the height you're at, so one gesture is a crescendo. Right-click the lane to randomize or reset.

The header

⧉ repeats the loop after itself. ÷2 / ×2 halve or double the rhythm — of the selection, or the whole roll. Changing grid re-meshes without moving the music (a quarter note on the 1/4 grid is four cells on the 1/16 grid). 🎧 auditions notes as you draw. ⌨ plays the roll's track from your typing keyboard (Study 9). →♪ converts the roll to the equivalent <…>*grid mini-notation, written into the pattern — handy when a drawn idea is done and you want to bend it in text.

Note rows, index rows

Every note carries two values: a pitch and a sample index (the thing .i() sets). The note / index button picks which one the rows show. On index the keyboard becomes 0, 1, 2, … — a pack's files — so pianoroll("chops").s("breaks") sequences a break by file, with lengths, velocity and probability meaning exactly what they do on the keyboard. Switching views moves nothing: draw a rhythm on one axis, set the pitches on the other.

In key

fold hides every row nothing is drawn on. With a setscale in force, the keyboard tints in-key lanes, scale shows only the key's notes (plus anything you drew), and the key chip snaps every note into the key. With scale on, →♪ writes degrees — n(`<0 2 4 ~>*16`).sc(3) — so re-keying later moves the notes too.

You never type the note string by hand — it folds to a small pill in the editor — but for the curious: pianoroll("60,0,4 64,0,4 67,8,8", { grid: 16 }) is midi[:index],start,len[,vel] per note, and it chains like note(): .scale(), .add(), and the rest.

Study 5

Instruments & effects

.synth("…") loads a VST/VST3 instrument; .fx("…") chains an effect after it (and after any earlier .fx()). Up to eight slots — one instrument, seven effects. The strings are the plugins' real names.

your rig, not mine This guide writes "Serum 2", "Diva" and so on as stand-ins — substitute plugins you actually have. Open sounds, hit rescan, and click any result to copy its exact name. Names also autocomplete inside the quotes. 
lead: note("c4 e4 g4 b4")
  .synth("Serum 2")
  .fx("ValhallaDelay")
  .fx("Pro-Q 3")

Parameters

.param("<real name>", value) sets any knob on whatever plugin is last in the chain — the plugin's own parameter names, no alias layer: 

.param("Filter 1 On", 1)
.param("Filter 1 Freq", 0.6)

To find names, evaluate once so the plugin loads, then open the params panel (sounds tab) — every parameter of every plugin in the chain, searchable, click to copy. They autocomplete inside .param("…") too. Values are 0..1 unless a mapping file in mappings/*.json gives them real units (one ships for Serum 2, so .range(200, 5000) on its cutoff means Hertz).

duplicate names Some plugins reuse a name across sections (Diva has three Frequencys). Plain .param("Frequency", …) hits the first; "Frequency#95" picks by index. The params panel and autocomplete show the #index form whenever a name collides.

Design a sound, keep it in the code

Double-click the synth or fx name (or click ui in the track panel) to open the plugin's own window for the fiddly stuff — unison, wavetables, a preset from its browser. Change anything there and the plugin's whole state is captured into the code for you, as a named preset: the call gains .preset("lead") and a folded definition lands at the foot of the buffer. Nothing to press, and the patch sounds identical on a cold start. 

lead: note("c4 e4 g4").synth("Serum 2").preset("<lead growl>")  // swap whole programs per cycle

Presets are just names, so they pattern. Double-click preset to open the panel where names are picked, made, copied and shaped by ear. export hands someone a single file that plays exactly what you hear; link puts a plain patch (no presets) on the clipboard.

Study 6

Modulation: making it move

Any .param() value can be a number, a mini string, an LFO or an envelope. This is where poptart earns its keep — modulation runs natively inside the audio engine, sample-accurate, with no per-note traffic.

LFOs

sine, saw, tri, square, ramp, rand, perlin. Each is a 0..1 shape; .range(lo, hi) rescales it. The rate is in cycles: sine(0.25) is one pass per four cycles, and it starts that pass on the cycle grid (0, 4, 8…) — a slow sweep is in the same place every time round. Write the unit for a rate that ignores the tempo instead: sine("0.5hz"). 

.param("Filter 1 Freq", sine(0.3).range(200, 5000))

lfo("…", { rate, mode }) is a hand-drawn shape. Double-click the word lfo and a shape editor opens — drag points, bend segments — writing the string for you as you go. Modes: free (its own clock), retrigger (phase resets on each note), envelope (once per note, then hold). The editor's playhead follows all three.

Envelopes

env({ attack, decay, sustain, release, curve }) is an ADSR retriggered by the track's own notes — times in seconds, sustain 0..1, .range() to scale: 

.param("Filter 1 Freq", env({ attack: 0.01, decay: 0.3, sustain: 0.2 }).range(300, 6000))

Knobs

The session tab has eight macro knobs, bound as macro1…macro8; drop one anywhere a signal goes. midicc("Twister")(12) is a hardware knob as a signal, bound natively — a real knob driving a real knob, no lag. 

.param("Filter 1 Freq", macro1.range(200, 4000))
tip .range()'s bounds can be signals too: lfo().range("200 300", 4000) sweeps from a stepped floor.

Study 7

The channel strip & the mixer

These live after the whole plugin chain, and take numbers, mini strings or any signal:

MethodDoes
.gain(v)Output level, 1 = unity. Chains multiply: .gain(0.5).gain(env()) is a level times a VCA.
.pan(v)−1 left … 1 right.
.width(v)Stereo width: 0 mono, 1 untouched, up to 4. Applied before the pan.
.bassmono(hz)Mono below hz, stereo above. The standard club-rig insurance.
.bus(name, amt)Aux send to a named bus; another track reads it with audio("name"). .dry(0) kills the dry; .bsend() is both at once.
.o(n)Which output pair: .o(2) = channels 3/4 (raise output channels in settings first).
pad: note("c3 e3 g3").synth("Diva")
  .width(0.6)                     // rein the patch's stereo in…
  .pan(sine(0.2).range(-1, 1))    // …then move it around
  .bus("space", 0.3)

verb: audio("space").fx("ValhallaRoom")

The mixer: ctrl+g

A strip per track — meter, fader, pan, width, mute/solo, a ▽ mono button for bass mono — plus a spectrum analyzer and a stereo image where anything spilling into the outer ø wedges is what a mono system will lose. The controls write code: a fader move rewrites the block's .gain(), mute and solo write _ / S on the label, and clicking a strip's name renames the pattern itself — the label, and any audio("…") / midi("…") that reads that track. The mix lives in the pattern and travels with the patch.

Study 8

The sampler

s("pack") plays a folder of audio files from your sample library (~/.poptart/samples by default — settings tab). Files are numbered in filename order, and everything runs through the same .fx() chain as an instrument. The sounds tab lists every pack; hold a file row to audition it. 

drums: s("bd*4, ~ hh ~ hh")   // "bd:4" picks a file inline = s("bd").i(4)
  .i("<0 1 2>")          // which file of the pack
  .begin(0).end(1)          // play region, 0..1
  .loop()                   // run off the end and carry on from 0 (.loopwrap(1) loops the region)
  .speed("1 -1")           // playback rate; negative = backwards
  .flip("<0 1>")           // reverse INTO the beat, landing on the next hit
  .stretch(2)               // timestretch, pitch preserved
  .slice("0 1 2 3")         // the nth transient (WAV only)
  .note("45 _ 52 57")       // repitch by MIDI note (c2 = as recorded)
  .vel("1 .5 ~ 1")          // per-hit volume (on synths: MIDI velocity)
  .adsr(0.1, 0.2, 0.6, 0.2) // amplitude envelope, as multiples of the hit's length

On a sampler, .note() / .n() repitch, and .scale() works as in Study 3. Patterned .note()/.vel()/.slice() are structural — each step retriggers, a ~ is a gap — so you can carve a beat out of one sample. Hits are gated: a sample rings for exactly its step and is cut there, so to let it ring longer make the step longer ("long/2", "long@2", ties).

loops & breaks .fit() repitches the whole file to a number of cycles (bare, the nearest power of two). .begin() then picks where to start inside it — so s("breaks:19").fit().begin(irand(8).seg(8).div(8)) is eight random slice starts a bar. If a fitted loop drops out, the region ran dry before the step ended: .loop() it, fire shorter steps, or start earlier. .log() on the track prints that arithmetic per hit.

Every control is also a top-level builder, which is how you reach into one channel from inside a transform — .mul(speed("-1")) flips whatever speed is in force: 

tops: s("breaks:19").fit().begin(irand(8).seg(8).div(8))
  .when(rand().gte(0.7), x => x.mul(speed("-1")))   // ~30% of bars backwards

One exact file: se() and sr()

se("path") names a file under the samples folder; sr("name") names one of your own bounces. Both are the same sampler. A path holds characters mini-notation reads as operators, so put it in single quotes: 

stab: se("'hits/stab 01.wav'").slice("0 2")
loop: sr("bass").slow(8)          // an 8-cycle bounce, played whole

A kit of your own: sp()

sp("kit") is a pack you put together file by file — eight hits from four folders, a drum rack. Evaluate a name nothing defines yet (or double-click sp) and the pack panel opens: click files to add, hold ▶ to hear one first, reorder with the arrows. Index it like any pack: sp("kit:0 kit:2 kit:1 kit:2"), or draw it in a piano roll's index rows.

The browser's search box looks through everything under the folder you're in, not just what's listed: type break in your samples folder and every file with that anywhere in its path comes back, wherever it's buried. Several words all have to match (break 170). Selecting a folder and pressing ← adds every audio file under it, subfolders and all.

Bounce a track: ctrl+b

Cursor in a block, ctrl+b: that track's audio is recorded from the next phrase boundary for the chosen cycles, filed under ~/.poptart/recordings/, and the bounce is written in below the (now muted) source under the same label: 

_bass: note("c2 eb2 g2 _").synth("Serum 2").record({ cycles: 8 })
bass: sr("bass").slow(8)

Same label on purpose: the bounce takes the original's place, so the mix doesn't move and un-muting one line puts the synth back. .record({ cycles }) in a chain gives you a panel with a live meter (double-click record).

Playing live

Study 10

Routing: midi() & audio()

Two builders move MIDI and audio between tracks, hardware and plugins. Each works in two positions, and the position decides what it does.

At the head of a track: a source

midi("KeyStep 32").synth("Serum 2")         // play Serum from a MIDI device
audio("drums").fx("ValhallaRoom")           // run another track through a reverb
input(3).fx("Amp Room")                    // a hardware input (channels from 1; two = stereo)

After an .fx(): an injector

bass: note("c2*8").synth("Serum 2").fx("Kickstart").midi("kick")  // duck to kick's rhythm
bass: note("c2*8").synth("Serum 2").fx("Pro-C 2").audio("kick")   // Pro-C's sidechain hears kick
kick: s("bd*4")

.midi("kick") replays the source's notes into the plugin (for MIDI-triggered duckers); .audio("kick") feeds its audio into the sidechain input (for compressors). .audio(input(1)) sidechains off a live mic.

A name resolves track-first, then against connected devices by substring. Force either: "track:kick", "dev:KeyStep".

tip For a trigger with no track of its own, make a muted one and point at it: _trig: note("c5 ~ c5 ~") then .fx("Kickstart").midi("trig").
note Hardware audio input needs a device that exposes inputs — pick one in settings. To use several interfaces at once, tick them under extra inputs; poptart combines them, and input("Scarlett", 1) then names whose channel 1 you mean.

Study 11

Transforms & combinators

Since patterns are signals, you reshape them with methods. Arithmetic takes its structure from the left side; the right can be a number, a string or another signal: 

note("c3 e3 g3").add(12)                      // up an octave
n("0 2 4").add("<0 7>").scale("C major")     // transpose every other cycle

The set: add sub mul div mod round abs floor ceil clamp, and the comparisons gte gt lte lt eq neq (1/0 — handy as conditions).

MethodDoes
.fast(f) / .slow(f)Playback rate. Negative plays in reverse. On an LFO, .fast() multiplies its rate.
.when(cond, fn)Apply fn wherever cond is truthy: .when("1 0", x => x.add(12)).
.degrade(p)Randomly drop events — the ?, as a method.
.ply(n, fn?)Retrigger each event n times; (x, i) => … shapes each repeat.
.echo(n, dt, fn?)n delayed copies, dt cycles apart — a pattern-level tape echo.
.arp(pat)Arpeggiate chords: note("[c3,e3,g3]").arp("0 1 2 3"). Indices past the top wrap up an octave.
.hold(trig) / .seg(n)Sample-and-hold at trig's onsets, or on an even grid of n per cycle: rand().seg(8) is stepped random.
.swing(amt, grid) / .nudge(v)Groove: s("hh*8").swing(1/3) is the triplet shuffle; nudge offsets each hit by a fraction of its step.
.vel(v) / .clip(v)Per-note velocity and length multiplier — on synths and samplers alike.

Every argument above takes a pattern, not just a number — .ply("<2 4>"), .seg("4 8"), .fast(macro1.range(1, 4)). If you find one that doesn't, it's a bug.

choose("0", "3", "7") picks one option per cycle (weight one with a [value, weight] pair); irand(8) is a random integer 0…7. Both drop in anywhere a signal goes: n(choose("0", "3", "7")), .vel(irand(2)).

independence Every rand(), perlin(), choose(), irand() and .degrade() is its own stream, seeded by position in the buffer — so two .when(rand().gte(0.7), …)s pick different bars, and a document replays identically every time. Pass { seed: 1 } when you want two randoms to move together.

Study 12

Making it yours

Extend the language

Signal.prototype is the shared prototype of every pattern, LFO and mini string. Add a method to it and everything — including bare strings — picks it up, exactly like Strudel's Pattern.prototype: 

Signal.prototype.acid = function () {
  return this.param("Filter 1 Freq", 0.3).param("Filter 1 Reso", 0.8);
};

bass: note("c2*8").synth("Serum 2").acid()

Such lines, and const … declarations, are ordinary setup: put them on their own column-0 line anywhere in the buffer. Three pitch helpers are exposed for writing your own: noteToMidi("c4"), degreeToMidi(2, "c minor"), parseScaleName("f dorian"). 

// a chord builder: intervals above a root, stacked into one mini "," layer
const chord = (root, ...ivs) => note(ivs.map((iv) => noteToMidi(root) + iv).join(","));

pad: chord("c3", 0, 4, 7, 11).synth("Serum 2")   // Cmaj7

Prebake: setup that runs at startup

Anything you'd paste at the top of every session — helpers, custom scales, prototype extensions — goes in the prebake, run once at load. Edit it from settings → edit prebake… (saving re-runs it) or in ~/.poptart/prebake.js; a ~/.poptart/prebake/ folder of *.js files runs after it, in name order. Its top-level bindings are in scope in every buffer: drums: kick just works.

★ The library

A drawn roll, an LFO shape, a preset or a pack lives in the buffer it was made in. Every picker shows a ★ beside each name: click it and the definition is copied into a prebake file poptart manages, and from then on pianoroll("bass"), lfo("swell"), .preset("growl"), sp("kit") resolve in every project. The buffer's own copy shadows the library's; draw into it and the star dims — click to update, ⇧click to take it out.

Hotkeys & editor scripting

The prebake runs in the browser too, so it's where you bind keys with hotkey(combo, handler) and script the editor through the editor handle (getSelection, replaceCode, getCode, …): 

// rotate the selected space-separated steps by one
hotkey("alt+r", () => {
  const { from, to, text } = editor.getSelection();
  editor.replaceCode(rotate(text.trim().split(/\s+/), 1).join(" "), from, to);
});

Combos are +-joined — cmd/ctrl/alt/shift/mod plus one key. bjorklund, rotate, clamp, prompt and log are on hand. ctrl+p/r/m/g are taken.
