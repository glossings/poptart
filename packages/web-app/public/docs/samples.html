Chapter 6

Samples

Play packs of audio files, chop them, stretch them, bounce your own.

Packs

s("pack") plays a pack of files, numbered from 0: "pack:3" is the fourth file (the same as .i(3)). A sampler takes .fx() like any instrument. 

drums: s("pt_kit:0*4, ~ pt_kit:3 ~ pt_kit:3, pt_kit:4*8").vel("1 .6").postgain(0.35)
bass: s("pt_keys:2").note("c2 ~ c2 eb2 ~ c2 g1 bb1").postgain(0.35)
bell: s("pt_keys:1").note("<g3 bb3 c4 eb4>").vel(0.5)
  .fx("Delay").param("Sync", "1/8.").postgain(0.35)

A pack is a folder in your sample library (~/.poptart/samples unless settings says otherwise); its files are numbered in name order. The sounds tab lists every pack: hold a file to hear it.

PackHas
pt_kita drum kit: 0 kick, 1 snare, 2 rim, 3 clap, 4 hat, 5 open hat, 6 low tom, 7 high tom
pt_keysone-shots at middle C: 0 pluck, 1 bell, 2 bass, 3 pad, 4 stab
pt_drumbox and pt_drumbox_kick, _snare, …a drum machine, and sweeps of each of its voices
pt_mallets · pt_piano · pt_perc · pt_synthmelodic and percussion packs

The first two are part of the page. The others download the first time a pattern names them and are kept after that. The sounds tab lists every pack: hold a file to hear it.

Your own files: drop audio on the window and it is kept in this browser as the files pack: s("files:loop.wav"). Dropped on the code, the s() that plays it is written where it lands.

A folder on this computer: settings → sample library → choose folder… makes a pack of each folder of audio in it. Nothing is copied; a file is read when a pattern first plays its pack. On a later visit the browser asks before the page may read the folder again (allow again). A browser that can't keep a folder has it for the visit and offers keep a copy, which copies the files into its own storage.

From GitHub: samples("user/repo") reads a public repository and makes a pack of each folder of audio in it, named after the folder. A share link carries the line, so whoever opens it hears the same files. A file is downloaded the first time it plays and kept by this browser; settings → downloaded packs says how much that is, and forgets it. 

samples("user/drum-kits")       // every folder of audio is a pack
samples("user/drum-kits@v2")    // a branch, tag or commit
samples("user/drum-kits/808")   // only that folder

beat: s("kicks:0*4, ~ snares:2")

Sampler controls

s("pt_kit:4*8")
  .begin(0).end(1)          // the region to play, 0..1
  .speed("1 -1")            // rate; negative plays backwards
  .note("c3 _ g3 c4")       // repitch: c3 plays as recorded
  .vel("1 .5 ~ 1")          // per-hit level
  .clip(2)                  // ring for two steps
  .adsr(0.01, 0.1, 0.8, 0.2) // envelope, in seconds; double-click adsr to draw it
  .loop()                   // keep looping for the hit's length
  .flip("<0 1>")            // play backwards into the next beat
  .stretch(2)               // twice as long, same pitch
s("hh*8")
  .begin(0).end(1)          // the region to play, 0..1
  .speed("1 -1")            // rate; negative plays backwards
  .note("c3 _ g3 c4")       // repitch: c3 plays as recorded
  .vel("1 .5 ~ 1")          // per-hit level
  .clip(2)                  // ring for two steps
  .adsr(0.01, 0.1, 0.8, 0.2) // envelope, in seconds; double-click adsr to draw it
  .loop()                   // keep looping for the hit's length
  .flip("<0 1>")            // play backwards into the next beat
  .stretch(2)               // twice as long, same pitch

A hit sounds for its step (times .clip()), then stops. To let one ring, give it a longer step ("a@2", "a _") or a bigger clip. A patterned control makes its own hits: s("x").note("c3 ~ e3") plays twice, with a gap.

Every control is also a builder, which reaches into one control from inside a transform: .mul(speed(-1)) flips whatever speed is set. 

kick: s("pt_kit:0*4").postgain(0.25)
hats: s("pt_kit:5*8").vel("1 .5")
  // about 3 bars in 10 backwards
  .when(rand().gte(0.7), (x) => x.mul(speed(-1))).postgain(0.25)

Loops and chops

WriteDoes
.fit(2) · .fit()repitch so the file lasts two cycles · the nearest power of two
.slice("0 1 2 3")play the nth chop (transients, found automatically)
.splice("<0 1 2>*8")each chop fitted to its hit; .splicemode("stretch") keeps the pitch
.slices("break")use the chops you drew (below)
// eight random starts a bar
tops: s("breaks:19").fit().begin(irand(8).seg(8).div(8))
// a loop you dropped: eight random starts a bar

If a fitted loop drops out, the region ran out before the step ended: .loop() it, or use shorter steps. .log() prints the numbers for every hit.

The slice editor

Double-click slice on a sampler chain to open the file with its chops drawn on it. Drag a numbered tab to move a chop; double-click to add one, right-click a marker to remove it; ←/→ walk through them. Markers snap to transients unless you hold alt; hold {mod} for fine moves. The wheel pans, {mod}-wheel zooms, {mod+0} fits.

fit sets how many cycles this file lasts, sens re-detects the chops (left keeps only strong hits, right finds ghost notes), grid chops evenly into 8ths, 16ths or triplets, and auto-slice goes back to detected chops.

What you draw is written into the code as a named set, used with .slices("break"). A set keeps markers per file, so one name covers a whole folder of breaks; [ / ] step to the other files the chain plays. Sets pattern: .slices("<tight loose>").

Grains

.grain() plays the sample as a cloud of short overlapping grains cut from around .begin(). It's still one voice per hit: .adsr() shapes the cloud and .note() pitches it. 

cloud: s("pt_keys:3").note("<[c3,eb3,g3] [bb2,d3,f3]>")
  .grain()                           // or .grain("<0 1>"), alternating
  .grainsize(0.08)                   // seconds per grain
  .grainrate(40)                     // grains per second
  .grainshape("pluck")               // each grain's window (double-click)
  .begin(saw(0.25).range(0.2, 0.6)   // a slow scan through the file…
    .add(rand().mul(0.02)))          // …each grain scattered around it
  .grainpan(rand().range(-0.6, 0.6))
  .adsr(0.4, 0.2, 0.8, 1.5)
  .fx("Reverb")
cloud: s("pad").note("c3 eb3 g3")
  .grain()                           // or .grain("<0 1>"), alternating
  .grainsize(0.08)                   // seconds per grain
  .grainrate(40)                     // grains per second
  .grainshape("pluck")               // each grain's window (double-click)
  .begin(saw(0.25).range(0.2, 0.6)   // a slow scan through the file…
    .add(rand().mul(0.02)))          // …each grain scattered around it
  .grainpan(rand().range(-0.6, 0.6))
  .adsr(0.4, 0.2, 0.8, 1.5)

Size, rate, pan and a .begin() with no rhythm of its own are read by every grain, so rand() scatters grains rather than notes and an LFO moves inside a held note. .bend() repitches grains the same way.

Your own kit: sp()

sp("kit") is a pack you put together file by file: eight hits from four folders. Evaluate a name nothing defines yet, or double-click sp, and the pack panel opens: click files to add them, hold ▶ to hear one, reorder with the arrows. Play it like any pack: sp("kit:0 kit:2").

The panel lists every pack as a folder: the built-in ones, what samples() read, your sample folder and the files you dropped. A kit can mix them. The search box looks through every file of every pack (break 170: all the words have to match), and ← on a selected pack adds all of it.

The search box looks through everything under the folder you're in, not just what's listed: break 170 finds every file with both words in its path. ← on a folder adds every audio file under it.

The sample map

The pack panel's map view (or map in the sounds tab) places each sound near the ones that sound like it, colored by what kind of sound its name and its neighbors' names say it is. Click a point to hear it, ← to add it to the kit.

← uniqueadd the sound least like anything already in the kit
⇄ · ] · [swap the selected entries for the next (or previous) sound like each
reshuffleswap every entry at once

The folders on the map are chosen in settings → sample map; the first build analyzes every file under them.

Every pack is on it unless settings → sample map narrows it. It's built the first time it opens, which reads every file of every pack once, so the first build is a download.

se("'hits/stab 01.wav'") plays one exact file under the samples folder (single quotes inside, because a path has characters mini-notation would read).

Bounce a track

With the cursor in a block, {app+b} records that track from the next phrase for the cycles you choose. The source is muted and the bounce is written under the same name: 

_bass: note("c2 eb2 g2 _").synth("Wavetable").record({ cycles: 8 })
bass: sr("bass").slow(8)
_bass: note("c2 eb2 g2 _").synth("Serum 2").record({ cycles: 8 })
bass: sr("bass").slow(8)

The mix doesn't move, and unmuting one line brings the synth back. Bounces are kept in ~/.poptart/recordings/in this browser and played with sr("name").
