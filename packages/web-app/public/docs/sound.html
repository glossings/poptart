Chapter 4

Instruments & effects

Load a sound, chain effects after it, set any control.

The chain

.synth("…") loads an instrument; each .fx("…") adds an effect after it. A chain holds up to twenty effects. 

lead: note("c4 e4 g4 b4")
  .synth("Wavetable")
  .fx("Chorus")
  .fx("Delay")
lead: note("c4 e4 g4 b4")
  .synth("Serum 2")
  .fx("ValhallaDelay")
  .fx("Pro-Q 3")

The names are your plugins' own. This guide uses "Serum 2", "Diva" and so on as stand-ins: use plugins you have. The sounds tab lists them (press rescan after installing one; click a name to copy it), and names autocomplete inside the quotes.

Every device is built into the page. The sounds tab lists them, and names autocomplete inside the quotes.

Controls

.param("name", value) sets a control on the last device in the chain, by the name its panel shows. The value can be a number, a pattern, or anything that moves (next chapter). 

keys: n("0 2 4 <5 7>").scale("D dorian").synth("Plaits")
  .param("Engine", "Chord")
  .param("Timbre", sine(0.2))
  .fx("Reverb").param("Mix", 0.35).postgain(0.6)
.param("Filter 1 On", 1)
.param("Filter 1 Freq", 0.6)

Every value is a 0..1 position on the control, and the device maps it to its real range (Cutoff runs 20 Hz to 20 kHz, so 0.5 is about 630 Hz). A list control takes its option's name ("ladder") or index; a switch takes 0 or 1. So an LFO or a macro drives any control as it is.

Values are 0..1 unless a mapping file in mappings/*.json gives them real units (one ships for Serum 2, so its cutoff takes Hertz). When a plugin reuses a name, "Frequency#95" picks one by index; autocomplete shows that form where names collide.

To find names, evaluate once, then open params in the sounds tab: every control of every device on the track, searchable, click to copy. They autocomplete inside .param("…") too.

Name a device first and .param() reaches it wherever it sits in the chain: .param("Delay", "Feedback", 0.6). When two devices share a name, "Filter#2" is the second of them in chain order. A label given as .fx("Filter", { label: "lo" }) is reached as "lo" however the chain is reordered. .wet() takes a device the same way. Inside a .when(), a control follows the condition, then yields: to a .param() outside the .when(), or, with none, to wherever the control was before. A .param() after the .when() wins over it, as a later call always does. 

keys: n("0 2 4 <5 7>").scale("D dorian").synth("FM")
  .fx("Filter", { label: "lo" }).param("Cutoff", 0.35)
  .fx("Delay").wet(0)
  .when("<0 1>", x => x.param("lo", "Cutoff", 0.7).wet("Delay", 0.5))

.wet(v) after a device blends it with what goes into it: 0 bypasses, 1 (the default) is fully processed. It takes a signal, so an effect can fade in over a song.

Presets

Double-click the synth or fx name to open the plugin's own windowdevice's panel. Change anything there and the whole state is captured into the code as a named preset: the call gains .preset("lead"), and the preset is kept in a folded block at the foot of the buffer. There is nothing to press, and the song sounds the same when it is next opened. 

// a different preset each cycle
lead: note("c4 e4 g4").synth("Wavetable").preset("<lead growl>")
// a different preset each cycle
lead: note("c4 e4 g4").synth("Serum 2").preset("<lead growl>")

Preset names pattern like anything else. Double-click preset to pick, make, copy and tweak them. export hands someone one file that plays exactly what you hear; link copies the patch without its presets. A share link carries the presets with the code.
