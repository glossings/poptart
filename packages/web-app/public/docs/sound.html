Chapter 4

Instruments & effects

Load a sound, chain effects after it, set any control.

The chain

.synth("…") loads an instrument; each .fx("…") adds an effect after it, as many as you like. 

lead: note("c4 e4 g4 b4")
  .synth("Wavetable")
  .fx("Chorus")
  .fx("Delay").postgain(1)

These devices are built in, the same as in the browser build. The sounds tab lists them, and names autocomplete inside the quotes. Your VST/VST3 plugins load the same way (below).

setscale("E minor")

bells: n("0 4 7 <9 11>").sc(4).synth("Rings")
  .param("Model", "'Sympathetic String'").param("Brightness", 0.6)
  .fx("GrainEcho").postgain(0.6)
pulse: note("e1*8").synth("Braids").param("Shape", "'Saw Sub'")
  .fx("Filter").param("Mode", "ladder").param("Cutoff", saw(0.5).range(0.25, 0.55))
  .fx("Overdrive").postgain(0.3)

Filterbank and Resonator move their bands' levels with Shape. In scroll mode each band shows what Shape was a moment before the band under it, so a sweep travels up the spectrum; in ripple mode Shape strikes the band at Where and the ripples bounce between the ends. Levels takes one cycle of a pattern, laid across the bands from low to high. 

setscale("D dorian")

pad: n("<0 3> [4 7]").sc(3).synth("Wavetable")
  .fx("Resonator").param("Shape", sine(0.5)).param("Decay", 0.4)
  .param("Levels", "<[1 0 .5 1] [0 1 0 .3]>")
  .postgain(0.5)
kick: s("bd*4")
  .fx("Filterbank").param("Mode", "ripple").param("Where", 0.2)
  .param("Shape", perlin(4)).param("Width", 0.3)
  .postgain(0.5)

Controls

.param("name", value) sets a control on the last device in the chain, by the name its panel shows. The value can be a number, a pattern, or anything that moves (next chapter). 

keys: n("0 2 4 <5 7>").scale("D dorian").synth("Plaits")
  .param("Engine", "Chord")
  .param("Timbre", sine(0.2))
  .fx("Reverb").param("Mix", 0.35).postgain(0.45)

Every value is a 0..1 position on the control, and the device maps it to its real range (Cutoff runs 20 Hz to 20 kHz, so 0.5 is about 630 Hz). A list control takes its option's name ("ladder", or "'Saw Sub'" for a name with a space in it) or index; a switch takes 0 or 1. So an LFO or a macro drives any control as it is.

A value written with a unit is in the control's own units: "3x", "800hz", "2khz", "-6db", "250ms", "7st", "50ct". A note name on a control in hertz is its frequency. A bare number is a position. 

bell: n("0 2 4 <5 7>").scale("D dorian").synth("FM")
  .param("Op 2 Level", 0.6).param("Mod 2 to 1", 0.5)
  .param("Op 2 Ratio", "<1x 2x 3.5x 7x>")
  .fx("Filter").param("Cutoff", "<1.2khz 4khz>").postgain(0.5)

To find names, evaluate once, then open params in the sounds tab: every control of every device on the track, searchable, click to copy. They autocomplete inside .param("…") too.

Name a device first and .param() reaches it wherever it sits in the chain: .param("Delay", "Feedback", 0.6). When two devices share a name, "Filter#2" is the second of them in chain order. A label given as .fx("Filter", { label: "lo" }) is reached as "lo" however the chain is reordered. .wet() takes a device the same way. Inside a .when(), a control follows the condition, then yields: to a .param() outside the .when(), or, with none, to wherever the control was before. A .param() after the .when() wins over it, as a later call always does. 

keys: n("0 2 4 <5 7>").scale("D dorian").synth("FM")
  .fx("Filter", { label: "lo" }).param("Cutoff", 0.35)
  .fx("Delay").wet(0)
  .when("<0 1>", x => x.param("lo", "Cutoff", 0.7).wet("Delay", 0.5))
  .postgain(1)

.wet(v) after a device blends it with what goes into it: 0 bypasses, 1 (the default) is fully processed. It takes a signal, so an effect can fade in over a song.

Parallel branches

.split() runs the chain in parallel and sums the branches; anything after it processes the sum. Each branch is a function that builds a chain on the signal it is handed, (x) => x is the signal as it arrives, and a branch's .postgain() and .pan() are its own level and place in the sum. Every device in every branch is on the same track, so notes routed in with .midi() strike a gate in any of them, and .param() reaches the device just before it, branch or not. Here two low-pass gates, one short and one long, sit either side of the dry synth: 

lead: note("c2 eb2 g2 <bb2 f2>").synth("Wavetable")
  .split(
    (x) => x.postgain(0.3),
    (b) => b.fx("LPG").midi("lead").param("Decay", 0.08).pan(-0.6),
    (b) => b.fx("LPG").midi("lead").param("Decay", 0.6).pan(0.6).postgain(0.7),
  )
  .fx("Reverb").param("Mix", 0.25).postgain(0.6)

.bands([frequencies], ...) splits by frequency instead, one function per band from the lowest up. The crossovers are Linkwitz-Riley, so bands left alone add back up to the input, and each one is a control: a number, a pattern or a signal, swept here. The devices in the bands number as they would in a .split(): the crossovers are not effects of the chain. 

drums: s("pt_kit:0*4, ~ pt_kit:4 ~ pt_kit:4")
  .bands([sine(0.1).range(150, 400), 2500],
    (low) => low,
    (mid) => mid.fx("Distort").param("Drive", 0.6),
    (high) => high.postgain(0.8),
  )
  .postgain(0.5)

Branches nest, and a .split() can sit inside a band, or a .bands() inside a branch.

Presets

Double-click the synth or fx name to open the device's panel (a plugin's own window, for a plugin). Change anything there and the whole state is captured into the code as a named preset: the call gains .preset("lead"), and the preset is kept in a folded _preset(…) line at the foot of the buffer. There is nothing to press, and the song sounds the same when it is next opened. 

// a different preset each cycle
lead: note("c4 e4 g4 [b4 c5]").synth("Wavetable").preset("<soft buzz>")
  .postgain(0.5)

Preset names pattern like anything else. Double-click preset to pick, make, copy and tweak them. export hands someone one file that plays exactly what you hear; link copies the patch without its presets. A share link carries the presets with the code. A device's preset opens the same in the browser build and the desktop app.

Your plugins

Any VST/VST3 instrument or effect you have installed loads by its own name, in the same places a device does. This guide uses "Serum 2", "Diva" and so on as stand-ins: use plugins you have. The sounds tab lists them (press rescan after installing one; click a name to copy it), and names autocomplete inside the quotes. 

lead: note("c4 e4 g4 b4")
  .synth("Serum 2")
  .fx("ValhallaDelay")
  .fx("Pro-Q 3")

Double-click the name to open the plugin's own window. What you change there is captured into a .preset(), as with a device. 

.param("Filter 1 On", 1)
.param("Filter 1 Freq", 0.6)
.param("Frequency#95", 0.3)   // the control at index 95, where two share a name

A plugin's values are 0..1 unless a mapping file in mappings/*.json gives them real units (one ships for Serum 2, so its cutoff takes Hertz: .param("Filter 1 Freq", sine(0.3).range(200, 5000))). When a plugin reuses a name, "Frequency#95" picks one by index; autocomplete shows that form where names collide.
